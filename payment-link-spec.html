Due Payment Link — Spec (MVP → Aggregator)

বাকির কাস্টমারকে লিংক পাঠান → ওরা টাকা পাঠিয়ে TrxID দেয় → দোকানদার এক ট্যাপে কনফার্ম → বাকি ক্লিয়ার। পরে অ্যাগ্রিগেটর যোগ হলে TrxID বাদ, অটো-কনফার্ম। প্যাটার্ন: job_public_tokens-এর মতোই।

কেন এটা প্রথমে

  • অ্যাগ্রিগেটর/API key ছাড়াই চালু হয় — আজই
  • দোকানদারের সরাসরি লাভ: বাকি আদায়ের জন্য লোক পাঠাতে হয় না
  • পেমেন্ট-রেভেনিউর আগের ধাপ: দোকানদারকে "ডিজিটাল কালেকশন"-এর অভ্যাস দেয়, পরে পেমেন্ট রেলে টানা সহজ

ডেটা মডেল (tenant স্কিমা)

due_payment_links
  id, tenant_token UUID (public URL-এ), customer_id, sale_id NULL,
  amount_due DECIMAL, note, status (open/submitted/confirmed/expired/cancelled),
  submitted_trxid VARCHAR, submitted_method (bKash/Nagad/bank/cash),
  submitted_at, confirmed_by, confirmed_at, expires_at, created_at

দোকানের পেমেন্ট নির্দেশনা tenant_pos_settings বা payment_accounts-এর নগদ/বিকাশ নম্বর থেকে দেখানো।

API

Method Path কাজ
POST /api/v1/dues/:customerId/payment-link লিংক তৈরি (amount + মেয়াদ)
GET /api/v1/dues/payment-links লিস্ট: open/submitted/confirmed — submitted আলাদা ব্যাজে
POST /api/v1/dues/payment-links/:id/confirm দোকানদার কনফার্ম → due allocation (আসল সার্ভিস পাথে)
GET /api/v1/public/pay/<token> পাবলিক — দোকানের নাম, বাকি, পেমেন্ট নির্দেশনা
POST /api/v1/public/pay/<token>/submit পাবলিক — method + trxid সাবমিট → status=submitted

পাবলিক রাউট auth নেই — টোকেনই অ্যাক্সেস (job_public_tokens প্যাটার্ন: URL-এ টোকেন, tenantResolver ছাড়া, catch-all-এর আগে মাউন্ট)।

UI

  • অ্যাপ/web: কাস্টমার ডিউ পেজে "📨 পেমেন্ট লিংক পাঠান" → লিংক কপি/WhatsApp শেয়ার; ড্যাশবোর্ডে "submitted" কাউন্ট + কনফার্ম বাটন
  • পাবলিক পেজ (/pay/<token> web রুট): দোকানের নাম-লোগো, বাকি টাকা, পেমেন্ট নির্দেশনা (বিকাশ/নগদ নম্বর, ধাপ), TrxID ফর্ম → "জমা হয়েছে, দোকানদার কনফার্ম করবে"

Aggregator-এ যাওয়ার ধাপ (পরে)

  • লিংকে "এখনই পে করুন" বাটন → অ্যাগ্রিগেটর checkout → webhook-এ status=confirmed সরাসরি
  • একই টেবিল/ফ্লো থাকে — শুধু submit ধাপ বদলায়
  • তখন MDR শেয়ারের কথা অ্যাগ্রিগেটরের সাথে

নিয়ম

  • টোকেন ৩২+ ক্যারেক্টার র্যান্ডম, মেয়াদ ৭ দিন ডিফল্ট
  • কনফার্ম শুধু দোকানদার — কাস্টমার কখনোই due ক্লিয়ার করতে পারে না
  • প্রতিটা কনফার্মে অডিট ট্রেইল (confirmed_by)
