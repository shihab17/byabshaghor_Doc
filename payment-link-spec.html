Payment & Collection Roadmap — ByabshaGhor

বাকি আদায় → পেমেন্ট রেল → MFS/ফ্লেক্সিলোড vertical → BanglaQR। স্ট্যাটাস: ✅ বানানো | 🟡 পরিকল্পিত | 🔴 লাইসেন্স/পার্টনার লাগে

Phase 0 — Due Payment Link (✅ শিপড, লোকাল)

দোকানদার কাস্টমারকে লিংক পাঠায় → কাস্টমার বাকি দেখে টাকা পাঠিয়ে TrxID দেয় → দোকানদার কনফার্ম → recordPayment দিয়ে বাকি ক্লিয়ার।

  • public.due_payment_links — token, tenant_id, স্ন্যাপশট (কাস্টমার নাম, due, দোকানের নাম, পেমেন্ট নির্দেশনা), status: open→submitted→confirmed/expired/cancelled, submitted_amount (partial payment সহ), মেয়াদ ৭ দিন
  • API: টেন্যান্ট /api/v1/due-links (create/list/confirm/cancel) + পাবলিক /api/v1/public/pay/:token (GET info, POST submit)
  • Web: /pay/[token] পাবলিক পেজ + কাস্টমার পেজে "Pay Link" বাটন (কপি/WhatsApp শেয়ার + submitted কনফার্ম)
  • Idempotent: client_ref = link.id — ডাবল কনফার্মে দুইবার লেখা না

Phase 1 — লিংক অটোমেশন (🟡 সহজ, এখনই করা যায়)

  • রিমাইন্ডারে লিংক: কাস্টমার পেজের Reminder বাটনে ক্লিক → ওপেন লিংক থাকলে সেটা, না থাকলে নতুন বানিয়ে WhatsApp মেসেজে বসায় — এক ক্লিকে কালেকশন চেষ্টা
  • বিক্রির পরে অটো-লিংক: due সহ sale হলে লিংক নিজে বানিয়ে ইনভয়েস/মেসেজে যোগ (feature flag)
  • শিডিউলড রিমাইন্ডার: cron — due ৭/১৪ দিন পুরনো বা লিংক মেয়াদ শেষের আগে অটো রিমাইন্ডার (sms/whatsapp মডিউল রিইউজ)

Phase 2 — অটো-ভেরিফাই (🟡→🔴 মার্চেন্ট অনবোর্ডিং লাগে)

রিসার্চ ফাইন্ডিং: bKash মার্চেন্ট API আছে (developer.bka.sh) — Tokenized Checkout, B2C Instant Payout, B2B Payout, Search Transaction by TrxID। Nagad-ও RSA-ভিত্তিক চেকআউট API দেয়।

উপায় কাজ লাগে
TrxID অটো-ভেরিফাই কাস্টমার TrxID দিলে searchTransaction কলে মিলিয়ে সরাসরি confirmed দোকানের bKash মার্চেন্ট অ্যাকাউন্ট + আমাদের ইন্টিগ্রেশন — ছোট কাজ, বড় UX জয়
Checkout বাটন লিংকে "এখনই পে" → bKash/Nagad checkout → callback/webhook → অটো confirmed মার্চেন্ট onboarding + callback হ্যান্ডলিং — TrxID ধাপই বাদ
B2C Payout দোকান → কাস্টমার রিফান্ড/ক্যাশব্যাক সরাসরি পরে

Phase 3 — BanglaQR (🟡 স্ট্যান্ডার্ডে ফিট)

  • এখন: পে লিংকে দোকানের BanglaQR ছবি দেখানো (payment_accounts-এ QR আপলোড ফিল্ড) → যেকোনো অ্যাপে স্ক্যান করে পে → TrxID জমা
  • পরে: চেকআউটে ডায়নামিক QR (পরিমাণ এমবেডড), রিসিপ্টে প্রিন্ট — acquirer ফরম্যাট জেনে জেনারেট
  • অটো-কনফার্ম: acquirer-এর webhook লাগে (BanglaQR নিজে জানায় না) — Phase 2-র সাথে একই জায়গায় পড়ে
  • সেলস অ্যাঙ্গেল: "এক QR-ই সব অ্যাপ" — দোকানদারকে আলাদা আলাদা QR ছাপাতে হয় না

Phase 4 — MFS/Flexiload Vertical (�→🟡 নতুন ভার্টিকাল)

দোকানদারের দ্বিতীয় ব্যবসা — এক অ্যাপে দুই খাতা। ডিমান্ড আগে ইন্টারভিউতে যাচাই।

কাজ সম্ভাবনা
ফ্লেক্সিলোড পুরো অটো ✅ অ্যাগ্রিগেটর API আছে — Supayo (flexiloadapi.com), FlexiloadBD, Success TopUp, iRechargeBD — এক ওয়ালেট, সব অপারেটর, রিসেলার কমিশন প্রকাশিত
MFS এজেন্ট রেকর্ড+কমিশন ✅ ফ্লোট অ্যাকাউন্ট ট্র্যাকিং + লেনদেন লগ + দৈনিক সেটেলমেন্ট রিপোর্ট
MFS এজেন্ট লেনদেন এক্সিকিউট ❌ API নেই — এজেন্ট USSD/অ্যাপেই করে; সেমি-অটো: tel:*247# ডিপ-লিংকে অ্যাপ নম্বর-টাকা ভরে দেয়, এজেন্ট শুধু পিন
ধূসর "USSD API" প্রোভাইডার ❌ বেটিং-সাইটমুখী, আইনি ঝুঁকি — না

নতুন ক্যাটাগরি "MFS Agent / Flexiload" — ফার্মেসির মতোই vertical প্যাটার্ন।

Phase 5 — রেভেনিউ লেয়ার (🔴 পরে)

  • MDR শেয়ার/রেফারেল: অ্যাগ্রিগেটর পার্টনার চুক্তি (PortWallet/aamarPay ছোটদের সাথে সহজ)
  • ফ্লেক্সিলোড রিসেলার কমিশন — সরাসরি আয়, পেমেন্টের চেয়ে আগে আসতে পারে
  • ডেটা → লেন্ডিং রেফারেল — দীর্ঘমেয়াদি
  • Model B (নিজেরা টাকা ধরে স্প্লিট) = PayFac, লাইসেন্স লাগে — এড়িয়ে থাকুন

সিদ্ধান্তের ক্রম — কী আগে

  1. ✅ Phase 0 (শিপড) — deploy করে লাইভে দেওয়া
  2. Phase 1 অটোমেশন — ছোট কাজ, সেলসে সাথে সাথে লাভ
  3. Phase 2 TrxID অটো-ভেরিফাই — মার্চেন্ট অ্যাকাউন্ট থাকা দোকানে; UX লাফায়
  4. Phase 3 QR শো — এক স্ক্রিনের কাজ
  5. Phase 4 ইন্টারভিউতে ডিমান্ড দেখে
